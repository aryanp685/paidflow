# Manual reminder composer — local implementation

This step only prepares user-controlled English, Hindi or Marathi message drafts. It is not deployed, scheduled, saved, sent, logged or tracked by Paidflow. Owners/admins/managers may choose an issued, non-archived invoice with a positive recorded balance. The active tenant and role come from `getWorkspace`; invoice/customer reads are tenant-scoped. The list uses stable ordering, pages of 50 and exposes at most the first 50,000 matching invoices. Query errors are shown as errors, not empty history. Actual Supabase RLS and provider integration are not yet tested.

The server populates an editable draft from the invoice, customer name, business name and balance at page load. That snapshot can become stale immediately: the user must verify recipient, invoice and current balance before sharing. The browser does not persist the draft, and navigating away loses edits. The user may explicitly copy the message or enter a recipient and choose to open WhatsApp or an email draft. The resulting external app, not Paidflow, controls sending; opening a link does not prove delivery. WhatsApp handoff discloses the user-entered number and message to WhatsApp, and URL data may remain in browser history. Email handoff passes the address and message to the configured email app. No recipients are auto-populated, no network handoff occurs on typing, and no sent/delivered claims are made.

No new reminder table writes, log records, follow-up scheduling, notifications, background jobs, or delivery integrations are implemented. Existing schema has separate reminder tables/policies, but they are not used by this feature. HTML email and attachment handling are absent. Hindi and Marathi are editable fixed starting templates, not full application translations or automated translation; each language has separate in-page edits. Native-speaker review remains necessary. Saved drafts, delivery tracking, schedule management and actual provider testing remain future work and need review. Existing issuance hold means fresh deployments with it cannot issue new invoices; reminders then apply only to already-issued invoices. Never assume the local implementation makes proof or invoice issuance safe, or that hosted migrations were applied.

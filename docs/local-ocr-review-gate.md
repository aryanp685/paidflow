# OCR review gate — design only, blocked

There is no production OCR pipeline, upload, extraction, review screen or save-from-OCR implementation in this step. Do not confuse the disabled storage lab's synthetic staging with scanned documents or a production OCR service. No file has been read or sent to a provider. Proof/document upload, preview and download remain on hold.

Before implementation, choose an approved document security pipeline and threat-model OCR input and output. A possible future sequence, **not an authorization to enable it**, is:

1. Authenticate and authorize active workspace membership. Accept files only through the separately approved quarantine/scanner pipeline; inspect the exact bytes and immutable version. Malware/scan errors, stale or absent attestation, unknown formats and storage failures must fail closed. Treat OCR engines/parsers and outputs as untrusted; isolate processing and cap CPU, time, pages and size. Sending data to any third party needs explicit privacy, residency and provider review.
2. Keep extracted fields in a tenant-scoped review staging area. Show source, uncertain/missing values and corrections without treating extracted text as verified. Users must review the fields and explicitly confirm; editing a field is not itself confirmation. Do not permit automatic save, issue, send, or payment recording from OCR. No document preview until that separate hold is lifted.
3. Validate corrected values server-side against permitted invoice schema, exact paise/rounding, role, tenant, source/version and current workflow state. Reject cross-tenant references, stale/revoked source, replay mismatch and incomplete review. Confirmation should atomically create only an authorized draft with an idempotency key and audit; concurrency, duplicate retries, cancellation and rollback need tests. Do not lift the issuance hold. Any design must preserve historical data and avoid claiming tax compliance.
4. Limit sensitive extraction fields and logging. The baseline currently grants tenant members SELECT on `document_extractions` (and includes JSON payload columns); it is not a safe substitute for least-privilege staging. Direct extraction writes are not granted to authenticated roles by the baseline. Review all direct PostgREST paths, grants, RLS, privileged workers, retention, deletion and incident response before any rollout.
5. Test benign samples, malformed inputs, tenant/role isolation, review edits and explicit confirmation, replay, outages, scanner revocation, race conditions, audit and no partial financial writes in isolated tests and a separately approved real-provider environment. Obtain independent security and financial review. No scanner installation, new cloud services, provider integration, migration or deployment is authorized by this design.

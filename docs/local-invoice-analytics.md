# Invoice analytics — local only

The workspace analytics page uses one tenant-scoped read of non-archived issued invoices, not marketing samples or fabricated metrics. It reports the count of those invoices, the number and total recorded balance of invoices with a positive balance, and overdue count and balance. Age buckets are not overdue (including due today), 1–30, 31–60, 61–90 and 91+ days overdue; the current date is the India calendar date. Amounts are accumulated with integer-paise `bigint`, including totals beyond JavaScript's safe integer range. Rows with zero balance do not appear in the aging table's counts. The data reflects stored invoice balances, not externally verified payment, GST accuracy or a guarantee that the ledger is correct.

The page performs a single bounded query for at most 1,000 rows and requests an exact count. It refuses to display totals if more than 1,000 invoices match, if the response is missing, fails, has a different row count (including a lower provider row cap), contains duplicate invoice IDs, invalid dates, or invalid/unsafe amounts. It does not combine multiple HTTP pages that may represent different snapshots. The result is as loaded and can become stale after loading; verify against the underlying invoices before decisions. The query does not summarize archived, draft or cancelled invoices, payment history, revenue over time, or forecasted collections.

The session/workspace guard and business-scoped filter apply; the existing baseline RLS permits all active tenant roles to read invoices. No new database migration or write path was introduced. Unit tests use mocked provider responses; real Supabase Auth, PostgREST counts/limits, RLS behavior, financial reconciliation, and concurrent/provider failure behavior have not been validated. A production-scale transactional aggregate with appropriate authorization and a separately reviewed rollout would be needed to remove the 1,000-invoice limit. The local issuance and proof holds remain undeployed, and the issuance hold would prevent new invoices being issued while active.

## 11. Previously linked proof — lab hold with history preservation

The lab's global hold denies grant, download and preview, including legacy valid grants, without fetching object bytes. The synthetic upgrade test starts with a legacy linked `verified` document and payment, applies the lab reclassification to `structurally_valid_unscanned`, and checks the previous invoice, payment and audit history survive. New attachment of that unscanned proof fails; idempotent historical replay remains available; after payment void, a valid old grant still cannot read bytes and the voided payment/history remain unchanged. Deletion/revocation of a linked record is blocked to preserve history. This is not an implementation of per-object quarantine or physical erasure, and does not prevent privileged direct object-storage access. Supabase has no equivalent production storage/hold implementation in this repo; do not claim this local result protects hosted files or existing links.

## 12. Dependency audit and targeted mitigation

On this branch, registry audit before changes reported **12 affected entries** (9 moderate, 3 high); `--omit=dev` reported zero. All four underlying advisory paths are in dev/test/build dependencies; that does not make them irrelevant in CI or prove absence of other vulnerabilities.

A **scoped override only for `@typescript-eslint/typescript-estree`'s `minimatch`** changes `10.2.6` to `11.0.5`, outside the parent's declared `^10.2.2` range. The affected parser source calls `minimatch(filePath, pattern, {dot:true})`; 13 synthetic glob cases were compared between 10.2.6 and 11.0.5 before installation, with no mismatches. A checked-in regression verifies those cases and real typed-parser project-service allowed/denied cases, plus lint, typecheck, unit tests and build. This limited compatibility evidence is not a guarantee for all glob patterns or upstream APIs. `11.0.5` requires Node 20 or >=22; tests here used Node 22.22.3, **not** deployed Node 26. Remove the override when a compatible upstream fix is available and re-run the checks.

After the targeted change `npm audit` reports **4 affected entries: 3 high, 1 moderate**, all in the local-only `s3rver@3.7.1` -> `busboy@0.3.1` -> `dicer@0.3.0`, and `s3rver` -> `fast-xml-parser@3.21.1` paths. Production-only audit remains **0**, not a security guarantee. No patched dicer release or compatible s3rver update was found in the current registry inspection. npm suggests a major s3rver downgrade; busboy and XML-parser major overrides break its documented usage and were not blindly applied. The guarded emulator stays on loopback with synthetic test data only, not real/untrusted files. These advisories remain **open**; future replacement requires independent compatible security testing. The production-boundary trace check confirms the emulator package is absent from the tested production graph, not every possible deployment artifact.
